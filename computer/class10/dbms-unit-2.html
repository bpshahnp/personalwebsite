2.5 · Types of Keys

Primary Key

DefinitionA primary key is a field or combination of fields that uniquely identifies each record in a table.

  • It ensures data integrity and helps establish relationships between tables.
  • It does not accept null or repeated (duplicate) values and cannot be left empty. It must always contain a unique value.
  • A table can have only one primary key.
  • It is compulsory to select one field as the primary key.
  • Primary keys can be used to refer to entire records, as each record has a different value for the key.
2.5 · Types of Keys

Uses of Primary Key

  • To identify each record uniquely.
  • To reduce data redundancy (duplication).
  • To set the relationship among tables.
  • Not to leave any field blank.

2.5 · Types of Keys

Foreign Key

DefinitionA foreign key is a field in one table that refers to the primary key of another table. It is used as a linking field to establish a relationship between two tables.

The importance of a foreign key:

  • It helps to establish a relationship between tables.
  • It ensures the existence of the referenced row in the primary table.
  • It helps to manage data integrity.
  • It is used to link rows in two different tables.

2.5 · Relationship

Relationship

DefinitionAn association established between the common field of different tables in a relational database is called a relationship. It is the connection between two or more tables in a database.

Relationships allow complex queries and help to extract data from multiple tables. There are mainly three types:

One to One (1:1)

One to Many (1:M)

or Many to One (M:1)

Many to Many (M:M)

2.5 · Relationship

One to One (1:1)

One record in a table is related to only one record in the other table, and the other way round. Every entry in the first table is uniquely matched with an entry in the second table.

Example: every citizen has his or her own passport, and no two passports are assigned to the same citizen. Each record in the Citizen table is related to only one record in the Passport table.

2.5 · Relationship

One to Many (1:M) or Many to One (M:1)

One record in a table is related to multiple records in another table, but each record in the second table is linked to only one record in the first. This type is very common in database design.

Example: a single teacher can have many students, but each student is assigned to only one teacher.

2.5 · Relationship

Many to Many (M:M)

Multiple records in one table can be related to multiple records in a different table. To implement this in relational databases, a junction table (also called a linking or bridge table) connects the two tables.

Example: the Study table links Student and Course. A single student can enroll in multiple courses, and each course can have multiple students enrolled.

2.6 · Query

Query

DefinitionA query is an important tool of a DBMS that allows you to retrieve, filter and manipulate data from your tables.

  • You can create queries to answer specific questions, combine data from multiple tables, calculate and aggregate.
  • A query is used to select data from one or more tables, or multiple linked tables.
  • It helps to sort, filter, update and modify the records in the database according to the criteria or conditions given by the user.
2.6 · Query

Advantages of using a query

  • To extract the selected records from various tables and assemble them for display in the form of a report.
  • To sort the records based on field names.
  • To find specific data quickly by filtering on specific criteria (conditions).
  • To calculate or summarize data.
  • To perform mathematical calculations on the given data.
  • To perform mass updates on the data of a particular field.
  • To delete the unnecessary data that is no longer required in the database.
  • To automate data management tasks, such as reviewing the most current data on a recurring basis.
2.6 · Types of Query

Types of Query

Queries are classified into different types depending upon the nature of operation. Some of the common queries are:

Select Query

The simplest type. Selects and displays data from a single table or multiple linked tables, using the criteria given by the user. It does not modify the original table. It displays the selected data in another table.

Update Query

Updates and modifies data in a single operation or click. Very popular because many records can be changed at one time. It directly modifies the original table.

Delete Query

Deletes or erases the unnecessary records that are present in the database, according to the criteria given by the user.

2.8 · SQL Constraints

SQL Constraints

DefinitionSQL constraints are the rules that limit the values that can be entered in a field.

  • They allow you to set a condition or criteria which limits the data entry in the table.
  • They specify the requirements for data entered into a table.
  • They ensure the validity of data, make it consistent, and play a vital role in maintaining the quality and integrity of the database.
  • Constraints can be applied when creating a table, or later using the ALTER TABLE statement.
NOT NULLUNIQUECHECKDEFAULTPRIMARY KEY
2.8 · SQL Constraints

NOT NULL

By default, a column holds NULL values. The NOT NULL constraint prevents a column from accepting NULL values.

Example

CREATE TABLE employee (
    Emp_Id int NOT NULL,
    Name varchar(255) NOT NULL,
    Address varchar(255),
    Salary int
);

Emp_Id and Name are defined with the NOT NULL constraint, so they cannot contain a null value and cannot be left empty.

2.8 · SQL Constraints

UNIQUE

The UNIQUE constraint ensures that all values in a column are different.

Example

CREATE TABLE students (
    Std_Id int NOT NULL UNIQUE,
    Name varchar(255) NOT NULL,
    Address varchar(255),
    Class int
);

Std_Id is defined with the NOT NULL and UNIQUE constraints. So Std_Id cannot contain a null value, and the value must be unique for each record.

2.8 · SQL Constraints

CHECK

The CHECK constraint is used to limit the value range that can be entered in a column.

Example

CREATE TABLE students (
    Std_Id int NOT NULL UNIQUE,
    Name varchar(255),
    Address varchar(255),
    Class int NOT NULL,
    CHECK (Class <= 12)
);

The CHECK constraint limits the value to be entered in the Class field. Only a Class less than or equal to 12 can be inserted into the table.

2.8 · SQL Constraints

DEFAULT

The DEFAULT constraint is used to set a default value for a column. The default value is automatically added to all new records if no other value is specified.

Example

CREATE TABLE students (
    Std_Id int NOT NULL UNIQUE,
    Name varchar(255),
    Address varchar(255),
    Class int DEFAULT 10
);

The default value of 10 is assigned automatically under the Class field if no value is provided for Class.

2.8 · SQL Constraints

PRIMARY KEY

The PRIMARY KEY constraint is used to set the primary key field for a column.

Example

CREATE TABLE students (
    Std_Id int,
    Name varchar(255),
    Address varchar(255),
    Class int,
    PRIMARY KEY (Std_Id)
);

The Std_Id field is defined with the primary key constraint. So Std_Id cannot contain a null value or a repeated value.

2.8 · Report

Report

DefinitionA report is the printed output that is created from a table or query.

  • Reports offer a way to view, format and summarize the information in your SQL database.
  • A report consists of information pulled from tables or queries, and information stored with the report design, such as labels, headings and graphics.
  • It is an object used to display and print data in an organized manner. We cannot add, modify or delete records in it.
  • Since it is the printed format of the database, a report is considered hard copy output.
  • MySQL can be connected to reporting tools like Power BI, Tableau or Google Data Studio to generate advanced graphical or printable reports.
2.8 · Report

Types of report

The different types of reports that can be generated with MySQL queries:

Summary Reports

Show total values like total sales or number of students.

Detail Reports

Display detailed records, for example a list of all employees with salary and tax.

Grouped Reports

Display records by categories like department or class.

Filtered Reports

Display reports based on certain conditions, for example employees with age greater than 45.

2.8 · Report

Advantages of a report

  • It is used to display the database in printed form on paper.
  • It is hard copy output, so it can be used for future use.
  • It is used to display and distribute a summary of data in printed form.

Key terms to remember

Data

Raw facts, symbols or unprocessed material.

Data Processing

Converting unprocessed data into meaningful information.

Information

The result after processing data. It gives complete meaning.

Database

An organized collection of logically related data.

DBMS

Software used to manage the data stored in a database.

RDBMS

A DBMS that stores data in linked tables of rows and columns.

Data Type

Defines what type of data a field can store: string, numeric, or date and time.

2.4 and 2.5 · Summary

Key terms to remember

Field

A column or attribute. The smallest unit of data in a table.

Record

A row or tuple. All the information about one entity.

Table

Also called a relation. Records (rows) and fields (columns).

Database System

Hardware, software, data and users working together.

Primary Key

Uniquely identifies each record. No nulls, no duplicates, one per table.

Foreign Key

A field that refers to the primary key of another table.

Composite Key

Several fields grouped together to act as the primary key.

Relationship

One to one, one to many, or many to many. Many to many needs a junction table.
